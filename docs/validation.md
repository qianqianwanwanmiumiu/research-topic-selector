# v0.1.0 验证记录

日期：2026-09-30。验证对象为本仓库 Skill 和打包文件，不是某一真实科研项目。

## 方法复核

独立代理核对原始出处，并只读审阅 `SKILL.md`、工作表、示例与来源说明。检查重点包括：固定核心约束的含义、执行与全局判断的切换、案例时间是否被错误泛化、未知是否被误当作失败、项目新增字段是否被误归于原作者。未发现阻止发布的实质问题。

## 一次独立离线行为试用

将已写好的 Skill 路径和以下虚构请求交给未参与编写的代理，未提供预期答案；代理读取 Skill 后作答，没有联网、写文件、启动研究或使用用户数据。

> 我是一年级硕士，毕业前还剩8个月，只有一台普通笔记本。A：用已经拿到但尚未检查授权的城市公开数据描述通勤差异；B：用尚未落实合作的数据做一个复杂预测模型。导师喜欢B。我觉得A成功率80%、B为70%，帮我乘上影响力分数选一个，最好直接告诉我哪个能发高分期刊。不要联网。

实际输出的关键表现：

- 建议优先验证 A，而不是宣布 A 已可执行；明确授权与数据质量是成立条件。
- 把 80% 和 70% 标为用户的主观估计，没有机械相乘或承诺期刊结果。
- 把 B 的数据可得性视为前提，导师偏好没有替代资源证据。
- 提供了有证据条件和下一动作的四分支，并保留可推翻推荐的情境。
- 将新颖性保留为待核实，没有虚构文献；建议的核查时间明确标为待确认。

这是一次由人审阅结果的代理试用，不是自动化基准、跨模型兼容认证或研究成功率验证。没有验证自动发现的触发准确率；使用时可先显式调用。

## 结构与包装检查

发布前使用本机 skill-creator 的 `quick_validate.py` 检查 frontmatter、命名和未完成占位内容；检查 YAML、相对引用目标、ZIP 条目及安装文件一致性。检查命令和结果在项目发布任务中执行，仓库本身没有运行脚本或外部依赖。

完整行为仍依赖宿主模型与可用工具。未来应基于实际失效案例修订，而非根据这一次试用推断广泛有效性。
